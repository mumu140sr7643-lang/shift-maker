## 0. まとめ

- 数理最適化（整数計画）を、ブラウザの中の Web Worker で HiGHS に解かせます。画面は固まりません。
- **段階的に解きます**：6連勤以上 → 「絶対」の決まり（1つずつ） → 「できれば」の決まり。各段の違反の量を最小にし、その値を「これ以上悪くしない」上限にして次の段へ。
- 計算の中の数は画面に出しません。**できた表を `check.js` で数え直して**、件数の帯・一覧に出します（確かめ役の別の数え方とも、同じ表で突き合わせられます）。
- 小分け：**3-1** 計算のしくみと node の道具（画面なし）→ **3-2** 手順5の画面（Worker・進み具合・中止・鍵・ぶつかりの確かめ）→ **3-3** 見本の「ちょうど良くきつい月」合わせ。

## 2. 変数（人×日）

| 変数 | 意味 |
|---|---|
| `x[人,日,シフト]` | その日そのシフトに入る（0/1）。**担当できるシフトだけ**作る（担当外は入れない） |
| `off[人,日]`・`paid[人,日]`・`spare[人,日]` | 公休・有給・余り日（0/1） |
| `ake[人,日]` | 明け（0/1）。夜勤の次の日と同じ値にする（式で縛る） |
| 半休 | 希望・固定にあるときだけ（自動では置かない） |

- 1人1日に、状態はちょうど1つ（空きは作らない）。
- 「出勤」（連勤の数え方）＝ シフト＋半休＋明け、は式の中で足し算で作ります（数え方の表の 1 章のとおり）。

## 3. 式で縛ること（どの段でも守る）

| 縛ること | 説明 |
|---|---|
| 1人1日1つ | 状態の合計が1 |
| 担当外は入れない | 担当できないシフトの変数を作らない |
| 希望・固定はそのまま | 希望の表のマス（休み・有給・半休・シフト）と、手で固定したマス（錠）はその値に決める。**空きのまま固定したマスは空きのまま（その人のその日は状態なし。連勤も休みの並びも切る）（B）**。手で入れて固定した明けは、前の日が夜勤でなくてもそのまま（C） |
| 日ごとに要るスキル | その日のそのシフトに、スキルを持たない人の変数を 0 にする |
| 夜勤の次の日は明け | 次の日が決まっていない（希望も固定も無い）ときは `ake[人,日+1] = 夜勤[人,日]`。**次の日が希望・固定で公休・有給・余り日・明けのときは、明けにしなくてよい（A・C）**。次の日がシフト・半休・空きの固定のときは、その日の夜勤は置かない。前の月の最後が夜勤なら、1日について同じ。自動で置く明けは、夜勤の次の日だけ |
| 公休は予定の数まで | 公休の数 ≦ 「月の公休数」と「希望・固定の公休の数」の大きいほう（D）。足りない分は「公休が足りない」の量。多すぎる分は余り日にする |
| 有給は設定の日数まで | 有給の数 ≦ 「有給の日数（切り上げ）」と「希望・固定の有給の数」の大きいほう（「有給の日数のずれ」を「なし」にしても、有給を休みの代わりに使いすぎないため） |

**解く前の確かめ**：`check.js` の `solveConflicts`（希望に**固定したマス**も入れたもの。固定と希望が違うマス、夜勤の次の日が空きのまま固定されたマスも見る）を使います。**止めるのは、式で縛っていて答えが無くなるもの（担当外・日ごとに要るスキル・夜勤の次の日・希望と違う）だけ**です（3-2 で確かめ役と決めた）。6連勤以上・連勤超過・遅い→早い・2連休は、式では量を最小にするだけなので止めずに作り、`unavoidableErrors` で「希望・固定のとおりにすると、次のエラーは避けられません」と出します（決まっていない夜勤の次の日は明けとして数える）。ぶつかりがあれば解かずに止め、「だれの・どの日の・何と何か・どの画面で直すか」を出します。それでも HiGHS が「答えが無い」と言ったときは「条件どうしがぶつかって作れませんでした」と出し、分かる範囲の手がかりを書き、**表は前のまま**にします。

## 4. 段の順番と、決まりの式

各段は「その段の違反の量（下の『量』）の合計」を最小にします。終わったら「その段の量 ≦ 最小値」を足して次の段へ進みます。

| 段 | 中身 | 量（最小にするもの） |
|---|---|---|
| 1 | 6連勤以上 | どの6日間（前の月の終わりも入れる）も出勤5日以下。超えた日数 |
| 2 | 人員不足（絶対のとき） | 1日・1シフト・1区分の足りない人数 |
| 3 | 公休が足りない（絶対のとき） | 足りない日数 |
| 4 | 連勤超過（絶対のとき） | 「上限＋1日」のどの続きも、出勤が上限以下。超えた日数（窓で数える） |
| 5 | そのほかの「絶対」の決まり（まとめて1段） | 下の表の量の合計 |
| 6 | 「できれば」の決まり（まとめて1段） | 下の表の量に重みを付けた合計 |

- 利用者が強さを変えた決まりは、その強さの段に入ります（「なし」は式に入れない）。説明書 4 節の順（人員不足 → 公休 → 連勤 → …）をそのまま使います。
- 6 段目の重みは、はじめはどれも 1（余り日の数は 0.5。人が多すぎる日に、出勤より余り日を選ぶため）。重みを変えるときは、6 章の測り方で前後を比べてから入れます。

| 決まり | 式（どれも、違反の量を表す0以上の数を足す） |
|---|---|
| 定数オーバー | その日・そのシフト・その区分の、必要人数を超えた人数 |
| スキル不足・スキルの目標に届かない | その日・そのグループで、スキルを持つ人（人数に数えるシフト）が最低・目標に足りない人数 |
| 1日1人の役が重なる | 1日1人の役のシフトの人数 − 1（0より大きい分） |
| 特別な日に決めた役職の人がいない | その役職以上の人の数が、決めた数に足りない分 |
| 遅い→早い | 遅い[日]＋早い[日+1] − 1（夜勤は「夜」なので入らない） |
| 遅い→休み→早い／2連休 | 遅い[日]＋休み[日+1]＋早い[日+2] − 2（休み＝公休・有給・余り日） |
| 1日だけの出勤・1日だけの休み | 休み[日−1]＋出勤[日]＋休み[日+1] − 2 など（明けは休みの側。夜勤の日は除く） |
| 連休が長すぎる | 「目安＋3日」のどの続きも、全部が休み（公休・有給・余り日）にならない |
| 連休の回数が足りない | 「目安の日数以上の連休が始まる日」を表す0/1を作り、その数が1回（連休にしたい人は2回）に足りない分 |
| 休み方の希望 | 連休にしたい人の1日だけの休み、ばらしたい人の3日続きの休み |
| 土日の希望 | 土日の出勤（休みたい人）・土日の休み（出たい人） |
| 時間帯の希望 | 合わないシフトに入る数 |
| 早い・遅いの偏り | 早い日数と遅い日数の差 − 許す日数（0より大きい分） |
| 連勤中の切り替え・切り替え回数 | **となりの日どうし**の早い⇔遅いの入れかわり（休みをはさむ入れかわりは式では見ない。数え方とのずれは、できた表を check.js で数え直して分かる） |
| 有給の日数のずれ | 有給の数＋半休×0.5 と設定の差 |
| 責任者の順位 | **1分で作るでは式に入れない**（人の組み合わせが多く、式が大きくなりすぎるため）。v6 の仕上げ（入れ替え）で減らす |

- 量と件数はちがいます（例：人員不足は「足りない人数」を最小にし、件数は check.js で数える）。どの答えを採るかは、件数で決めます（6 章）。

## 5. 時間の区切りと記録

- 1分で作る：合計 約60秒。段 1：10秒、段 2〜5：あわせて30秒（段ごとに残りを分ける）、段 6：残り全部。
- HiGHS には、差を0で解くように頼みます（`mip_rel_gap = 0`）。
- 段ごとに残すもの：「解ききった（差0で最適）」か「時間切れ（途中の答え）」か、かかった秒、その段の量。時間切れで答えが1つも無いときは、前の段の答え（前の段の上限を満たす）をそのまま使い、「時間切れ（前の段の答えのまま）」と残します。
- 「最後まで解ききった」と画面に書くのは、全部の段が「解ききった」ときだけです。
- **段1で時間内に答えが1つも無いとき（F）**：表は前のまま、「時間内に作れませんでした」と出し、スタッフの数・希望の数の見直しと、じっくり作る（v6）を案内します（v3 のうちは、もう一度ためす・1分を延ばすことはしない）。
- 記録は `month.runs` に足します（作り方・時刻・段ごとの結果）。いちばん新しい 20 回ぶんまで残します。

## 6. 確かめ役も同じ条件で回せる道具と、測り方

`node tools/solve.mjs 保存したファイル.json --nodes 2000 --out フォルダ`

- 時間ではなく「調べる数の上限」（HiGHS の `mip_max_nodes`）で区切り、乱数の種（`random_seed`）と計算の線の数（`threads = 1`）を決めておくので、**同じデータ・同じ上限なら、同じ答え**になります（パソコンの速さで答えが変わらない）。
- 出すもの：段ごとの結果（解ききったか・量・秒）、できた表（このアプリで取り込める形の JSON）、その表の `tools/count.mjs` と同じ形の JSON。全部フォルダに保存します。
- `--time 60` を付けると、画面と同じく時間で区切ります（こちらはパソコンの速さで答えが変わります）。

**採るか捨てるかの決め方（測る前に CLAUDE.md に書く）**

- 式や重みを変えるときは、同じ作り物の月（8・15・25・50人／28・30・31日／人手が足りない月・固定の無い月 など、何種類も）を、前と後で **3回以上**ずつ作って比べます。
- 比べ方は `check.js` の `isImproved` と `compareResults`（説明書 3 節の「改善」と並べる順）。6連勤以上と「絶対」のどの決まりの件数も、どの月でも増えない変更だけを採ります。合計が減っても採りません。
- 「3回以上」の意味：調べる数で区切るときは、**乱数の種を3つ（1・2・3）変えて3回**。時間で区切るときは、同じ条件で3回。
- 式で正しく数えている決まり（6連勤以上・人員不足・公休が足りない・連勤超過 など）は、**段の最後の量と、できた表を check.js で数えた量が同じか**を道具で確かめます（式の作りまちがいを見つけるため）。近い形で数えている決まり（切り替え・責任者の順位）は、違ってよいものとして分けて出します。

**答えが無いにならないことの確かめ（E。`tools/solve-stress.mjs`）**

- 作り物の月に、希望と固定を乱数でたくさん入れて（休み・有給・半休・シフト・空きの固定・明けの固定・夜勤の次の日の休み・前の月の最後の夜勤 など）解き、「答えが無い」が出たら、そのときは必ず `solveConflicts` が1件以上ある、ことを確かめます。
- 答えが出たときは、できた表で `check.js` の 担当外のシフト・希望と違う・日ごとに要るスキル・夜勤の次の日 が 0件で、固定したマスが1つも変わっていないことを確かめます。

## 7. 手順5の画面（3-2）

- 作り方を選ぶ：「1分で作る（おためし）」（v3）・「じっくり作る（本番）」（v6 までは「準備中」）。大きなボタン「シフトを作る」。
- 押すと、まず解く前の確かめ（3 章）。いまの表にマスがあるときは「いまのシフト表は、作った表に置きかわります（固定したマスと希望はそのまま）。いまの表は控えに残します」と確かめ、控え（理由「自動で作る前」）を残します。
- 計算中は、画面の上に小窓を出して、ほかの操作（入力・手順の移動・月の切り替え・取り込み）を止めます（止めた理由を書く）。小窓に「段 3/6 公休が足りない」「◯秒たちました（あと最大◯秒）」「いまのいちばん良い答え：絶対◯件・できれば◯件」（段が終わるたびに check.js で数える）と「中止」。
- 「中止」で Worker を止め、表は前のまま。
- 計算は**写し**で行い、終わってから本物の表に入れます（入れる前に、そのあいだにデータが変わっていないか確かめます）。
- 作り終えたら：件数の帯と同じ数、時間切れだったか・最後まで解ききったか、「つぎにやること」（手順6で見る・エラーの一覧・もう一度作る）。
- 計算のあいだは、ほかの重いアプリを閉じるよう書きます。

## 8. 速さの見込み

- v0 の試し（決まりを少しだけ入れた式、node）では、10〜30人×31日で1つの段が0.1〜0.3秒でした。
- 全部の決まりを入れると変数と式が増えます（50人×31日で、変数はおよそ 50×31×(シフト数＋5)＝1万〜1.5万、式は数万）。3-1 で node の道具で測り、1分の配分で答えが出るか、どの段が重いかを報告します。重すぎる決まりは、量の式を軽くするか、v6 の仕上げに回すかを、測ってから決めます。

## 9. 見本の「ちょうど良くきつい月」（3-3）

- 見本3つを、1分で作るで3回ずつ作り、件数を数えます。
- 「エラーが少しだけ出る」をめざします（案：6連勤以上 0、絶対 1〜5件、できれば 数件〜20件。確かめ役と決める）。
- 見本のスタッフの人数・公休の数・必要人数を少しずつ変え、前後の数を CLAUDE.md に残します。
- 見本を変えると、snapshot の見本のファイル（12個）が変わります。変わるのは見本だけで、作り物の月と古い形のデータは1文字も同じであることを確かめます。

## 10. 相談したいこと

| # | 所 | 決めたこと（確かめ役と決めた） |
|---|---|---|
| 1 | 責任者の順位 | 1分で作るの式には入れない。ただし軽い式（1日1人の役のシフトに入る人に、順位が下の人ほど小さな重みを足す。たし算だけ）を 3-1 で1回試して測り、6 章の決め方で採るか決める |
| 2 | 切り替えの数え方 | 式では、となりの日どうしの入れかわりだけを見る。できた表の check.js の件数との違いを 3-1 の報告に書く |
| 3 | 見本の「ちょうど良くきつい」の目安 | 6連勤以上 0、絶対 1〜3件、できれば 5〜20件。見本3つとも、種を3つ変えて3回作り、いつもこの中に入ること |
| 4 | 生成の前の控え | 表にマスがあるときだけ、控え（理由「自動で作る前」）を残す。控えの文と、控えから戻せることを ui_check.py に足す |
| 5 | 半休 | 自動では置かない（希望・固定のときだけ） |
