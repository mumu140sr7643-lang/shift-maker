# 詳しい説明書（利用者から 2026-10-31 に受け取ったもの・原文のまま）

この説明書は、作る係・確かめ役の両方が読むものです。作る係は、前に送った文に加えてこの説明書に沿って作り、全体の作り方の案もこれに合わせて出し直してください。確かめ役は、作る係の案と各版がこの説明書に沿っているかも確かめてください。

【詳しい説明書】業種を問わず使えるシフト表の自動作成アプリ

この説明書は、作るアプリの画面・動き・決まりを、できるだけ細かく書いたものです。コードはありません。ここに書いた考え方をもとに、一から作ってください。全部を一度に作る必要はなく、最後の「版の分け方」の順に少しずつ作ります。ここに書いていない細かい所は、使う人に分かりやすい形を自分で考え、迷ったら利用者に質問してください。

====================================================================
1. 全体の考え方
====================================================================
- ブラウザだけで動く（サーバーは使わない）。データはブラウザに保存し、ファイルに書き出して持ち運べる。GitHub Pages で公開する。
- 1か月分のシフト表を作る。行がスタッフ、列が日。マスにシフトの記号（または休み）が入る。
- 作り方の流れを、左のメニューの「手順1〜6」にする。
  1 基本設定 → 2 シフトの種類 → 3 スタッフ → 4 希望の入力 → 5 自動で作る → 6 シフト表（確認・手直し・書き出し）
  各画面の下に「前へ」「次へ」。
- 見る人がすぐ試せるよう、初めて開いたときは「業種の見本」を選ぶ画面を出す（飲食店・小売店・介護施設など）。選ぶと見本の設定とスタッフ（名前は A・B・C…）が入る。あとで「リセット」すれば選び直せる。

言葉の決まり（画面で使う言葉。業種の言葉にしない）
- シフトの種類: 「朝」「夜」「日勤」など。中の名前（変わらない番号のようなもの）と、画面に出す記号・名称を分ける。記号は利用者が自由に変えられ、変えても表や希望は崩れない。
- 時間帯のグループ: 「早い時間帯」「遅い時間帯」（必要なら「夜」）。休む間隔・切り替えの決まりはこのグループで数える。
- 役職: 順位のある役職（例: 店長・リーダー・スタッフ）。名前も数も自由。
- 1日1人の役: 「その時間帯の責任者」のように、1日に1人だけ入る役のシフト。
- スキル: 「レジ」「調理」「資格あり」など。スタッフが持つ。
- 雇用の区分: 「社員」と「パート・アルバイト」。必要人数を区分ごとに持てる（合わせて数える設定も）。
- 休みの種類: 公休（月に取る休み）、有給、半休、研修（人数に数えない出勤）、余り日（人が多すぎて出勤させずに置く日。公休には数えない）。

====================================================================
2. 画面ごとの動き
====================================================================
【手順1 基本設定】
- 対象の年月。年月を変えるときは、前の月の日付つきのデータ（表・希望・固定・日ごとの人数など）を片付けるか聞く（「やめる」「先に書き出してから片付ける」「片付けて切り替える」）。スタッフや設定は残す。ちょうど次の月へ進むときは、片付ける前に前の月の表から「月末の連勤日数」と「最後のシフト」を読み取って、スタッフに引き継ぐ。
- 勤務の決まり（数を入れる）: 連勤の上限（例: 5日）、遅い時間帯の次の日に早い時間帯を禁止するか、1日だけの休みを避けるか、連休の目安。
- 特別な日（イベント日・繁忙日など）: 日を選び、その日に入れたい役職の人数などを決める。
- 詳しい設定（ふだんは閉じた折りたたみ）:
  - 決まりごとの強さ: 決まりごとに「絶対」「できれば」「なし」を選ぶ（下の「3. 決まり」）。
  - 必要人数の決まり: 「土日は朝を3人」「毎月10日は夜を+1人」のような条件つきの人数。
- 設定を変えたら、表があればエラーをその場で数え直す（表は作り直さない）。

【手順2 シフトの種類】
- 表: 記号・名称・時間帯のグループ・労働時間・ふだんの必要人数（社員・パート）・詳細。
- 詳細（行を開くと出る）: 人数に数えるか、研修扱いか、夜勤か（夜勤の次の日は休み）、社員とパートを合わせて数えるか、Excel に出すときの色、削除。
- 「シフトを追加」: 小窓で、記号と名称・時間帯のグループ・夜勤か・人数に数えるか・ふだんの必要人数（はじめ0人。特定の日だけ使うシフトのため）・担当する人、を聞いてから足す。まずい答え（記号が空・重なる・休みの記号と同じ・表計算で式に読まれる「=」「+」「-」「@」で始まる）は小窓の中に理由を出す。
- 日ごとの必要人数（折りたたみ）: 日×シフトの表で、日ごとに人数を上書きする。
  - ふだんの数（決まりが当たればその数）と同じ数を入れたら、上書きを消す。
  - 決まりで決まった日は点線の下線、上書きした日は色を変え、マウスを置くと「ふだんは◯人」と出す。
  - キーボードで続けて入れられる: 押すと数字が選ばれ、打つと置き換わる。Enter で次の日、Shift+Enter で前の日、↑↓で上下の行。Shift を押しながら日を押す（なぞる）と何日か選べ、数字を打って Enter で全部に入る。Esc でやめる。ホイールで数字は変わらない。
- 日ごとに要るスキル: 「この日のこのシフトには、このスキルを持つ人だけ」を日ごとに指定（いくつか並べたら、どれか1つでよい）。

【手順3 スタッフ】
- 左に一覧（名前・役職・区分・担当シフト）、右に選んだ人の詳細。スマホでは一覧を押すと詳細へ移る。
- 詳細: 名前、区分、役職、担当できるシフト（チェック）、スキル（チェック）、月の公休数、有給の日数、時間帯の希望（早い時間帯だけ・遅い時間帯だけ・どちらも）、早い・遅いの偏りの希望（均等・早い多め・遅い多め）、休み方の希望（連休・ばらす）、土日の希望、個人の連勤上限、「遅い→早い」の間は2連休にする、前月末の連勤日数・最後のシフト、メモ。
- 追加・削除。削除したらエラーを数え直し、その人の固定も消す。スタッフの番号（中の名前）は、消した人の番号を使い回さない。

【手順4 希望の入力】
- 日×スタッフの表。上に入れる記号を1列に並べる（休み: 休・有給・半休 ｜ 出勤を固定: 各シフトの記号 ｜ 消す）。押してからマスを押すと入る。
- 表のいちばん下の行に「あと何人休めるか」（その日、出られる人数 − 必要人数）。0 の日は赤系、1 の日は黄系、マイナスはいちばん強い色。1以下が2日以上続く所を囲み、「きつい期間」と分かるようにする。
- 希望を入れたその場で、新しく0人の日・きつい期間ができたら、画面の下に知らせる（「この希望を取り消す」「閉じる」）。
- 希望だけで必ずエラーになるもの（同じ日に休み希望と固定がぶつかる など）は、表の上に知らせる。

【手順5 自動で作る】
- 作り方を選ぶ: 「1分で作る（おためし）」「じっくり作る（本番。最大10分ほど）」。大きなボタン「シフトを作る」。
- 計算中は進み具合（いまの段・いまのいちばん良い答えの件数・経過秒）と「中止」。計算中はほかの操作（入力・月の変更・取り込みなど）を止め、止めた理由を出す。
- 作り終えたら、結果の文（エラーの件数、時間切れだったか、最後まで解ききったか）と「つぎにやること」の案内。
- 詳しい機能（折りたたみ）: 作る前の見込み（下の「5」）、人手の余り・不足の表、エラーを減らす設定の案、希望の変え方を確かめる、など。
- 計算のあいだは、ほかの重いアプリを閉じるよう書く（計算は時間で区切るので、パソコンが混むと答えが悪くなる）。

【手順6 シフト表】
- 表のマスはシフトの時間帯グループで色分け。1日1人の役は太字。休み・有給などは記号。
- エラーの印（3段階。形と色で分け、重なっても見分けられる）:
  - 6連勤以上（働きすぎ）: 濃い赤の太い枠＋右上に四角
  - 絶対の決まり: 赤い枠＋右上に丸
  - できれば: 黄土色の点線＋右上に三角
  - 余り日: 青緑の縞
  - 手で固定したマス: 左上に錠の印。作ったあとに手で変えたマス: 左下に点。
- マスにマウスを置くと、そのマスのエラーの文。
- 上の帯: 「元に戻す」「やり直す」「その他の操作」（CSV・検査し直す・まとめて固定・途中から作り直す・固定をすべて外す など）「Excel に出す」。
- 件数の帯: 6連勤以上・絶対・できれば・余り日・不足（足りないコマ数）の件数と、主ボタン「エラーを自動で直す」。帯の「余り」「不足」を押すと内訳の枠が開く。
- 帯の下: 不足があるとき「予定どおり休みを取らせると◯コマ足りません」と、多い順に6行（「◯日の朝が1人足りません［理由を見る］」「Aさんの公休を2日削って出勤で埋めています」など）。
- 表の下: 日ごとの必要人数の行（手順2と同じ入れ方）と、配置した人数。足りない日は色。
- マスを押すと、シフトを選ぶ小窓。ドラッグで2人のマスを入れ替え。変えたらその場で検査し直し、悪くなったら「悪くなりました: 連勤超過 2→3件」のように知らせる（止めはしない）。
- 集計表: 人ごとの各シフトの回数・公休・有給・出勤日数・労働時間。

====================================================================
3. 決まり（エラーの種類）
====================================================================
- それぞれ名前は1つ（設定の画面とエラーの一覧で同じ名前）。強さは利用者が選ぶ（「絶対」「できれば」「なし」）。「なし」にした決まりは数えない。
- 一覧（かっこは既定の強さ）:
  - 人員不足（絶対）: その日そのシフトに必要人数より少ない。1日・1シフトで1件、足りない人数も持つ。
  - 定数オーバー（できれば）: 必要人数より多い。
  - 連勤超過（絶対）: 連勤の上限を超える。1続きで1件、超えた日数も持つ。前月末からの続きも数える。
  - 6連勤以上（働きすぎ・いつも最重要）: 上限の設定にかかわらず6日以上続けて出勤（半休も出勤に数える）。ほかの「絶対」とも分けて出す。
  - 遅い→早い（休みなし）（絶対）: 遅い時間帯の次の日に早い時間帯。
  - 遅い→休み→早い（できれば）: 1日だけ休んで時間帯が変わる。
  - 連勤中の時間帯の切り替え（できれば）: 続けて出勤している途中で早い⇔遅いが変わる。
  - 時間帯の切り替え回数（できれば）: 月の切り替えが上限（例: 2回）を超える。休みの日は直前の時間帯を引き継いで数える。
  - 早い・遅いの偏り（できれば）: 「均等」の人の偏りが許す日数を超える。「早い多め」の人は早い側に寄っていてもよい（足りない側だけ数える）。
  - 1日だけの出勤（できれば）・1日だけの休み（できれば）
  - 連休が長すぎる（できれば）・連休の回数が足りない（できれば）
  - 公休が足りない（絶対）: 予定の公休数に届かない。足りない日数も持つ。
  - 有給の日数のずれ（できれば）: 設定の日数と違う。
  - スキル不足（絶対）: その時間帯に、そのスキルを持つ人が最低人数より少ない（研修・人数に数えないシフトに入っている人は数えない）。
  - スキルの目標に届かない（できれば）
  - 責任者の順位（できれば）: その時間帯にいる人のうち、順位がいちばん上の人が1日1人の役に入っていない。
  - 1日1人の役が重なる（絶対）
  - 担当外のシフト（絶対）・時間帯の希望と合わない（できれば）・夜勤の次の日が休みでない（絶対）
  - 特別な日に決めた役職の人がいない（できれば）・休み方の希望と合わない（できれば）
  - 日ごとに要るスキルを持たない人が入っている（絶対・変えられない）
- エラーの文は、だれが読んでも分かる文にする（「12日 朝の「レジ」ができる人が1人（最低2人）。研修に入っている1人は数えていません」）。シフトは中の名前ではなく、利用者が付けた記号で出す。

良し悪しの比べ方（とても大事。合計件数だけで判断しない）
- 「改善したか」: 次をすべて満たし、どれかが減ったときだけ改善。
  1) 「絶対」のどの種類の件数も増えない（種類をまたいで取り替えない。人員不足1件を消して連勤超過1件を作る案は改善ではない）
  2) 連勤の超過日数が増えない
  3) 6連勤以上の件数が増えず、新しく・長く・つながっていない
  4) 公休の足りない日数の合計が増えない
  5) 「できれば」は、「絶対」がすべて同じときだけ比べる
- 「どれが良いか並べる」（何通りかから選ぶ・案を並べる）の順:
  6連勤以上の件数 → 人員不足 → 「絶対」の合計 → 連勤の超過日数 → 公休の足りない日数 → 「できれば」の件数
- 自動の処理（作る・仕上げ・自動修正）は、6連勤以上を新しく作らない・長くしない・つなげない。手で直して6連勤以上になったときは、止めずに知らせる。

4. 自動で作るしくみ
====================================================================
- 数理最適化（整数計画）を、ブラウザの中の Web Worker で解く（例: HiGHS の WebAssembly 版）。画面は固まらない。
- 変数: 人×日×シフトの「入る／入らない」、と休みの種類。必ず守ること（式で縛る）: 1人1日1つ、担当外は入れない、希望・固定はそのまま、日ごとに要るスキル、夜勤の次の日は休み、など。
- 段階的に解く（大事な順に1段ずつ）: 各段で、その段の罰点（違反の量）を最小にし、その値を「これ以上悪くしない」上限として固定して、次の段へ進む。
  - 最初の段: どの6日間も出勤5日以下（働きすぎを作らない）。
  - 次に「絶対」の決まりの段（人員不足 → 公休 → 連勤 → …）。
  - そのあと「できれば」の段。利用者が「絶対」にした決まりは、「できれば」の段より先に解く。
- 1つの段に時間の上限を付ける（1分で作る: 合計約60秒。じっくり: 合計約10分）。時間内に解ききれた段と、時間切れで途中の答えの段を区別して記録する。「最後まで解ききった」と言えるのは、差を0で解いて最適と出た段だけ（差を許して止めた答えを「これ以上良い答えは無い」と言わない）。
- 何通りか同時に解く: 段の順番や時間配分を変えた解き方を、Web Worker を何本か使って同時に解き（CPU の数 − 1、最大4）、3の「並べ方」でいちばん良い答えを選ぶ。
- 仕上げ: 解いたあと、各人の出勤・休みの日数と、各日の役割ごとの人数を変えない入れ替え（同じ日の出勤どうしの入れ替え、2人×2日のたすき掛け）で、検査で確かめながらエラーを減らす。
- じっくり作るときは、先に1分で作る答えも作り、それを出発点・保険にする（じっくり側が悪ければ1分側を使う）。
- 計算中は一度に1つだけ。「中止」で全部の Worker を止め、結果は反映しない。試しに計算するとき（比べるだけ）は、本物の表・設定を書き換えない（写しで解く）。
- 余り日: 人が多すぎて必要人数を超える分は、出勤にせず「余り日」にする（公休には数えない）。

5. 作る前・作ったあとの助け
====================================================================
- 作る前の見込み（実現性チェック）:
  - 日ごとの余裕（全体・早い時間帯・遅い時間帯・スキルごと）。0の日は、出られる人が全員出勤になることを、その人たちと一緒に出す。
  - 「どう作っても最低◯件のエラーになる」見込み（作れた表の件数を超えないように、少なめに数える）。理由（「4日〜6日は、前月末の連勤があるので6連勤を作らずに出せる人日が◯足りない」など）と、直し方のボタン（その希望を外す など。押す前に、押すと本当に減ることを計算で確かめる）。
  - 月の合計の人手（必要な人日と、出られる人日。区分ごと）。
- 人手の余り・不足の表（できることごと）: 行は「全体」「役ごと（1日1人の役・時間帯）」「スキルごと」。列は 余り・不足／必要／出られる／埋められる／足りない日。埋められる数は、人を日と枠に1人1日1つずつ割り当てる最大流で数える（「出られる − 必要」の引き算だと、ある日にしか入れない人を何日ぶんにも数えてしまう）。希望・固定のとおりにすると休み・有給を削ることになる行は、その日数を出す。
- 不足の理由の枠: 足りないマスで「理由を見る」と、その日そのシフトを担当できる人が、なぜ入っていないかを1人ずつ出す（休みの希望・有給・別のシフトに固定・入れると連勤の上限を超える・遅い→早いになる 等）。決まっていない人は、写しの表に入れて検査にかけ、新しく出るエラーで言う。「担当を足せば入れられる人」も出す。
- その場の知らせ: 必要人数・希望・設定を変えて、休める人が0人の日やきつい期間が新しくできたら、画面の下に「22日は、休める人が0人になります。21〜23日は、あと1人以下の日が続きます」と、何を変えたからかを書いて知らせる。戻したら消す。
- エラーを自動で直す: いまの表から、変えるマスの数に上限（10・25・50・全部）を付けて解き直し、出たものから案として並べる（変わるマスの数・件数の前後）。「絶対」がどの種類も増えない案だけ。利用者が選んで反映し、元に戻せる。
- 途中から作り直す: ◯日までをそのまま固定して、あとの日を作り直す。
- エラーを減らす設定の案: 「連勤の上限を1日増やすと」「この日の必要人数を1人減らすと」など、設定を1つ緩めた場合の件数を試算して並べる。
- 余り日の使い道: 余り日を、教わる人の出勤（指導役と同じ時間帯）に回す案。試しに作って比べてから反映。
- 診断レポート: エラーの原因（人手が足りない・特定の役ができる人が少ない・時間帯を両方こなす人に切り替えが集中 など）と対処を、文で出す。

6. データの安全
====================================================================
- 元に戻す・やり直す: 手直し・入れ替え・自動修正・必要人数の変更・生成（生成する前の表へ戻れる）。変えた所だけを履歴に積み、戻すときは「いまもその値のままの所」だけ戻す。
- 自動で保存（ブラウザ）。書き出し・取り込み（取り込む前に中身を全部確かめ、正しくなければ断って、いまのデータのまま）。保存データが読めないときは、別の場所に控えを残して知らせる（見本で上書きしない）。
- 取り込んだ文字（名前・記号）は、そのまま画面の HTML に入れない（文字として扱う）。
- 読み込むファイルに版の番号を付け、版を上げたら番号も上げる（キャッシュよけ）。画面の隅に版を出す。

7. 見た目
====================================================================
- 色は CSS の変数だけで持つ（明るい・暗いの両方）。読みにくい文字（コントラスト 4.5:1 未満）0、スマホ幅（390px）で横のはみ出し0。
- アイコンは線画。エラーの3段階は形でも分ける（色が見分けにくい人のため）。
- 文は短く、専門の言葉を使わない。押したら何が起きるかが分かるボタンの名前。
- 手引き（使い方のページ）: 「まず、これだけ」→「毎月やること」→ 画面ごとの説明 → エラーの見方 → 困ったとき。画面の名前と手引きの名前を1文字も違えない（突き合わせる道具を作ると良い）。

8. 業種の見本（最初に選ぶ）
====================================================================
いずれも、スタッフは A・B・C… の作り物。ちょうど良くきつい月（エラーが少しだけ出る）にする。
- 飲食店: 朝（早い）・昼（早い）・夜（遅い）、時間帯責任者（朝・夜。1日1人の役）。役職: 店長・リーダー・スタッフ。スキル: 調理・レジ。社員とアルバイト。週末は人数を増やす決まり。
- 小売店: 早番・中番・遅番、売場責任者（1日1人の役）。役職: 店長・主任・スタッフ。スキル: レジ・品出し。セール日（特別な日）に役職者を入れる。
- 介護施設: 早出・日勤・遅出・夜勤（夜勤の次の日は明けで休み）。役職: 管理者・リーダー・スタッフ。スキル: 資格（例: 看護）を時間帯ごとに最低1人。

9. 版の分け方（おすすめ）
====================================================================
- v1 土台: 業種の見本・手順1〜4の画面・手で表を作る（マスを押して選ぶ）・保存・書き出し・取り込み・明るい／暗い・スマホ。
- v2 検査: 決まりと強さ・エラーの3段階の印・一覧・その場で検査し直す・件数の帯。
- v3 自動で作る（1分）: Web Worker と数理最適化、段階的に解く、中止、計算中の鍵。
- v4 手直しの道具: 元に戻す・やり直す・入れ替え・エラーを自動で直す・途中から作り直す・Excel／CSV。
- v5 見込みと説明: 作る前の見込み・あと何人休めるか・その場の知らせ・人手の余り不足の表・不足の理由。
- v6 じっくり作る: 何通りか同時・仕上げ・1分の答えを保険に。
- v7 手引きと紹介ページ: 画面の写真、使った技術の説明、試すリンク。
- そのあと: 余り日の使い道・設定の案・診断レポート・日ごとに要るスキル・必要人数の決まり・月の切り替えと引き継ぎ。

10. 測り方（作る係・確かめ役とも）
====================================================================
- 生成は回ごとにぶれる（時間で区切るため）。比べるときは、同じデータで3回以上。何通りかの答えを全部保存しておけば、選び方の変更はあとからかけて比べられる。
- 「絶対」と「できれば」を分けて数える。合計が減っても「絶対」が増える変更は採らない。数えなくしただけで減った変更も採らない。
- 作り物の月を何種類も作る（人数・休みの希望の位置・30日の月と31日の月・人手が足りない月・固定の無い月）。1つの月にだけ合う変更にしない。
- 作る前の見込み（最低件数）と比べ、届いている月はそれ以上減らせないと分かる。
- 理屈で良さそうな変更も、測って悪くなれば取り消す。
