## 0. まとめ

- 段1：いまの式（build.js が HiGHS に渡す LP の文）を、そのまま CP-SAT の形に移して、Python の ortools（ふつうのパソコン用）で解き、HiGHS の「1分で作る」と比べます。**6段の流れ（上限を足す・ヒントを渡す・時間の配分・答えが無いときの守り）は Python の側で全部回します**（段ごとに Python を立ち上げ直すと、その時間も60秒に入ってしまうため）。node の道具は、式を作って渡し、返ってきた答えを build.js の readTable で表にし、check.js で数える係です。
- 段2：段1 で「採る」に届いたときだけ、パソコン版（まず Windows）の案を作ります。
- 決め方（確かめ役が決めた。測る前）：
  - 採る：次の2つを両方満たすとき。
    - 18か月 × 3回で、CP-SAT（Worker 8・60秒）が HiGHS の「1分で作る」より並べる順で悪い回が無い（絶対・6連勤以上が増えない）。
    - かつ、できれば の平均が2割以上少ない。
  - HC8（下の 4 章）にも同じ決め方を当てます。C8 と HC8 の両方が届いたら、できれば の平均が小さいほうを採ります。
  - 採らない：どちらも届かないとき。パソコン版は作らずに、6-2 を予定どおり HiGHS で続けます。
  - パソコン版でも HiGHS は使えます（画面の中の WASM、または Python の highspy）。HC8 を採るなら、その形で作ります。
  - どちらになっても、6-1 の仕上げの入れ替えはそのまま使います。
- 「悪い回が無い」の数え方（確かめ役が決めた）：
  - 月ごとに、C8 の3回（種 1・2・3）× H の3回 の 9組。18か月で 162組。
  - 重い所（並べる順の、できれば より前の全部：6連勤以上・人員不足・「絶対」の合計・連勤の超過・公休の不足）で、C8 が悪い組が 0。
  - できれば は、C8 の54回の平均が、H の54回の平均の 0.8 倍以下。
  - あわせて報告するもの：並べる順の全部で比べた 良い・同じ・悪い の数（162組）。月ごとの「C8 のいちばん悪い回 と H のいちばん良い回」。C8＋仕上げ と H＋仕上げ も同じように。
- 測った ortools の版と、このパソコンの CPU（16。8コア）も報告に書きます。

## 2. 式の移し方（LP の文 → CP-SAT）

- 入れるもの：build.js の `model.lp(段の式, 前の段の上限)` が作る LP の文そのもの。HiGHS と全く同じ式になります（式の作りまちがいを2つの部品で同じに持つため）。
- 道具 `tools/cpsat_run.py`：この LP の文（Minimize・Subject To・Binary・End だけを使う、こちらで作る形）を読んで CP-SAT の式にし、6段を順に解きます。
  - 2択の変数 → 0〜1 の整数。
  - 量の変数（違反の量・公休の不足など。LP では 0 以上の数）→ 0 以上の整数。上限は、どれも「その月の日数 × 人数」（半日の数にした変数は、その2倍）。小さく決めすぎると本当の答えを切ってしまうので、次の2つで確かめます。
    - 答えの値が上限にぴったり当たっていないか（当たっていたら止めて知らせる）。
    - 小さな月で、上限を4倍に広げても同じ最小値になるか（`tools/cpsat-same.mjs`）。
- **整数でない所と、どう整数にしたか**（build.js を読んで分かったもの）

| 所 | 整数でない数 | 整数にするやり方 |
|---|---|---|
| 有給の日数のずれ（`paidDiff`） | 半休は有給 0.5 日・設定の有給の日数が 4.5 日など | その式を2倍する。ずれの量の2つの変数（多い・少ない）を「半日の数」にする（いまの量 = その数 ÷ 2） |
| 「できれば」の段の余り日の重み（`_spare`） | 0.5 | 「できれば」の段の式全体を2倍する（ずれの量の半日の数は、2倍したので重み 1） |
| 前の段の上限 | LP では `最小値 + 0.000001` | 整数にした式で「≦ 最小値」（ぴったり） |
| 変わるマスの重み（`_change` 0.001）・責任者の重み（`leaderWeight`） | 1分で作るでは使わない | 段1 では入れない（出てきたら止めて知らせる） |

  - 道具は、移したあとの式の係数がどれも整数かを確かめ、整数でないものが残っていたら止めます。
- 段の順：HiGHS と同じ6段（6連勤以上 → 人員不足 → 公休 → 連勤 → ほかの絶対 → できれば）。
  - 各段のあとで「その段の量 ≦ 見つけたいちばん小さい値」を足して、次の段へ進みます。
  - 前の段の答えは、ヒント（`solution_hint`）として渡します。
- 時間の配分：HiGHS と同じ（段1 は合計の 1/6、段2〜5 は合わせて 1/2、残りを「できれば」の段）。
  - 時間内に「これ以上は無い」と言えた段は「解ききった」、そうでない段は「時間切れ」として記録します。
  - 時間内に答えが1つも無ければ、前の段の答えのままにします（HiGHS と同じ守り）。
- 答えは、build.js の `readTable`（変数の名前 → 値）で表にし、check.js で数えます（HiGHS と同じ道）。
- 式が正しく移ったかの確かめ（`tools/cpsat-same.mjs`。小さな月 8 個の全部の段）：
  - 入れる確かめ（解かないで済む）：HiGHS が解いた各段の答え（変数の値）を CP-SAT の式にそのまま入れて、全部の式を満たすか・上限の中か・段の量が HiGHS と同じか。CP-SAT の式が「きつすぎる」（本当の答えを外す）ことを見つける。
    - HiGHS の値の小数のずれ（0.999998 など）は、1e-5 までは丸めて入れる。段の量は 1e-4 まで同じとみる。
    - そのまま入らないとき：HiGHS では、その段で重みの無い量の変数が小数をとれる。そこで、2択の変数を HiGHS の値に決めて、量の変数だけを CP-SAT に選ばせ、段の量が HiGHS 以下になるかを見る。
  - 解く確かめ：CP-SAT で6段を解き、前の段までの量が同じあいだ、段ごとに比べる。HiGHS が解ききった値より CP-SAT の量が小さければ、CP-SAT の式が「ゆるすぎる」。
  - 両方がそろえば、移し方が正しいと言えます。

## 3. 道具（node）

- `node tools/cpsat.mjs 保存したファイル.json [--workers 8] [--time 60] [--seed 1] [--ub-times 1] [--hybrid] [--out フォルダ]`
  - `--hybrid`（HC8）：「できれば」より前の5段は、いまの HiGHS（stages.js の solveStaged をそのまま、1分で作ると同じ配分）で解く。「できれば」の段だけを CP-SAT で解き、HiGHS の段の量を上限として足し、HiGHS の表をヒントに渡す。時間は 60秒の残り全部。
  - 式を作って `tools/cpsat_run.py` に渡し、6段を Python の側で全部解かせます。60秒には、式を読む・作る時間も入れます（Python と ortools を読み込む時間は別に記録）。
  - 出すもの：段ごとの結果（解ききったか・量・秒）、できた表（取り込める JSON）、`count.mjs` と同じ形の数、Python のメモリのいちばん多い所（Windows の PeakWorkingSet）、ortools の版。
- `node tools/cpsat-same.mjs`：式が正しく移ったかの確かめ（小さな月で、HiGHS と CP-SAT が両方「解ききった」段の最小値が同じか、上限を4倍にしても同じか、上限に当たっていないか）。
- `node tools/cpsat-bench.mjs [--only H,C8,C4,C1,C8-600,finish,summary]`：下の 4 章の測りを回し、全部の答えを保存して、比べの表を作ります。
- Python は、ふだんの Python を変えないよう、別の箱（venv。`try-ortools-parts\venv`）のものを使います（`SHIFT_MAKER_PYTHON` で場所を渡す）。

## 4. 測り

**月**：説明書の測り C と同じ 18か月です。
- 見本3つ × 2026年11月・2027年2月・5月・8月。
- 作り物 6通り：
  - 8人×2027年2月（28日）・15人×2026年11月（30日）・25人×2026年12月（31日）・50人×2026年12月（31日）。この4つは希望も固定も無い月です（solve-bench --sizes と同じ作り方）。
  - 人手が足りない月：8人×2026年11月（人員不足が 60件ほど出る月）。
  - 希望のある月：20人×2027年5月（make-sample の希望を残す）。

**作るもの**

| 名前 | 中身 | 回数 |
|---|---|---|
| H | HiGHS の「1分で作る」（ほかに何も動かしていないとき。60秒） | 3回 |
| H＋仕上げ | H の答えに 6-1 の仕上げ（上限 25秒） | 3回 |
| C8 | CP-SAT Worker 8・60秒・種 1・2・3 | 3回（決め方に使う。1つずつ、ほかに何も動かさない） |
| C8＋仕上げ | C8 の答えに 6-1 の仕上げ | 3回 |
| HC8 | 「できれば」より前の5段は HiGHS、「できれば」の段だけ CP-SAT Worker 8・種 1・2・3（合わせて 60秒） | 3回（決め方に使う。1つずつ、ほかに何も動かさない） |
| HC8＋仕上げ | HC8 の答えに 6-1 の仕上げ | 3回 |
| C4 | CP-SAT Worker 4・60秒・種 1・2・3 | 3回（報告だけ。4コアのパソコンの人の目安） |
| C1 | CP-SAT Worker 1・60秒 | 1回（報告だけ） |
| C8-600 | CP-SAT Worker 8・600秒 | 1回（報告だけ） |

- 同時に動かすのは、合わせて 8本（8コア）まで。H・C8・HC8 は1つずつ、ほかに何も動かさずに回します（C4 は2つずつ、C1 は8つずつ）。
- 確かめ役も同じパソコンで重い確かめを回すので、H・C8・HC8 を測り始める前と、測り終わったときに、確かめ役に直接知らせます。

**報告に書くもの**
- 月ごとの 6連勤以上・絶対・できれば の件数（H・H＋仕上げ・C4・C4＋仕上げ・C1・C2・C8・C4-600）。
- 並べる順で、C8 と H を比べた 良い・同じ・悪い の回数（162組）。C8＋仕上げ と H＋仕上げ、HC8 と H、HC8＋仕上げ と H＋仕上げ も同じく。
- 時間内に答えが出なかった回数（段1 で答えが無い）、使ったメモリのいちばん多い所。
- C8・HC8 の答えにも仕上げをかけたら、さらに減るか。
